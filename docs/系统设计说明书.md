# 青智方舟系统设计说明书

架构设计　数据设计　接口设计　界面与交互设计　设计评审

## 一、架构设计

### （一）架构选型

选型结论：分层单体，单机单进程，浏览器访问本机端口。不是微服务，不是前后端分离，不是无服务架构。这个结论由产品形态直接决定——交付形态是可本地运行的交互原型，数据全部本地处理不上传，不设登录鉴权，不依赖付费或需审批的外部接口。这些条件叠加起来，一个进程加一个浏览器页面就是完整的系统边界。

| 维度 | 微服务的适用条件 | 本项目的实际情况 |
| --- | --- | --- |
| 部署规模 | 需要独立扩缩容的服务群 | 单机运行，无扩缩容需求 |
| 团队规模 | 多团队各自负责一个服务 | 三人或单人，拆分只增加沟通成本 |
| 调用开销 | 服务间网络调用可接受 | 全部计算在同一台机器内，跨进程调用纯属浪费 |
| 运维成本 | 有专门的运维支撑 | 无，且交付周期内不允许引入 |
| 数据边界 | 各服务拥有独立数据 | 全部数据在一份参数文件与一份画像里，拆不开 |

### （二）系统分层

| 层次 | 职责 | 主要产出 | 对应模块 |
| --- | --- | --- | --- |
| 参数层 | 管理模型参数与典型用户画像，参数带来源与性质标记 | 参数表、画像库 | 目标与收入录入、典型画像库 |
| 仿真层 | 对收入与支出做随机过程建模并做多情景推演 | 现金流路径、目标达成概率 | 现金流仿真沙盘 |
| 决策层 | 按规则分配账户资金、生成备选方案、测算风险容量 | 账户分配方案、二选一方案、容量等级 | 价值分层账户、风险容量、多目标优化 |
| 解释层 | 生成术语解释与结果解读，把数字翻译成自然语言 | 术语三层解释、结论文案 | 金融术语三层拆解 |
| 呈现层 | 组织界面、绘制图表、处理交互 | 界面、图表、演示素材 | 成长护照及全部界面 |

### （三）跨层调用的例外约定

原文档规定每层职责单一、不允许跨层调用。实际存在两处必要的中转，此处补齐例外条款。

其一，多目标优化模块需要重复调用仿真层。二选一方案属于反向求解，需要给定目标反推预算，每次评估都要重新触发推演。处理方式是在决策层与仿真层之间开放一个受控的求解器接口，并约定三条约束：只能通过该接口重复调用；搜索过程中的每一次评估必须复用同一批随机路径；求解必须设定迭代上限与无解判断。

其二，容量日历需要逐月重算。每月都要用当期安全垫厚度重新分级，等同于对仿真结果做按月切片的二次计算。这部分计算放在仿真层完成并缓存为独立的日历结构，呈现层只负责绘制，不在渲染时重算——切换图表的交互频率远高于重算频率，把计算压在渲染路径上会直接影响界面响应。

### （四）部署架构

单机单进程。启动后在本机端口提供服务，用户通过浏览器访问。无独立数据库进程，无缓存服务，无消息队列。仅监听回环地址，从网络层面保证画像数据不出本机，这比在应用层做上传拦截更可靠。

唯一的外部依赖是术语模块可能调用的大模型接口。该接口不可用时术语模块必须能降级运行，降级开关放在参数文件中，默认关闭，演示时按现场网络情况决定是否开启。依赖以清单文件声明，支持一键安装；图表中文字体在启动配置中显式指定，避免出现方框乱码。

### （五）架构决策与权衡

| 决策 | 选择 | 放弃 | 理由 |
| --- | --- | --- | --- |
| 架构风格 | 分层单体 | 微服务 | 单机运行，拆分只增加成本 |
| 前后端 | 同进程 | 分离 | 约束明确要求无需前端能力 |
| 存储 | 本地文件 | 数据库 | 数据量小，无并发，无需事务 |
| 随机路径 | 生成一次，全局复用 | 每次仿真重新抽样 | 可复现要求与性能预算双重约束 |
| 容量日历 | 仿真层算好缓存 | 渲染时实时计算 | 交互频率高于重算频率 |
| 术语生成 | 模板为主，模型为辅 | 纯模型生成 | 必须保留离线降级路径 |

## 二、数据设计

### （一）存储方案选型

| 方案 | 适用条件 | 匹配度 |
| --- | --- | --- |
| 纯文件（CSV 与 JSON） | 数据量小、无并发、无需事务、需人工编辑 | 高。参数需人工编辑并核对来源，单用户无并发 |
| SQLite | 需要关系约束、按条件查询、单机写入 | 中。能提供约束，但参数人工编辑的体验反而变差 |
| 数据库服务 | 多用户、并发写入、远程访问 | 低。与数据不上传外部服务器的要求直接冲突 |

选型结论：以纯文件为主。参数需要人写人手，二十余条参数的八个字段与三档取值必须在表格软件或文本编辑器里完成，纯文本文件可以直接打开编辑。数据量极小，单用户单进程，不存在并发写入竞争。若后续要实现决策历史记录并希望按时间检索，可引入 SQLite 单表存储，但不作为本次设计的默认方案。

### （二）逻辑数据模型

共十三类实体，其归属关系如下：用户画像由目标与收入录入模块产生，其下包含收入来源、人生目标、悦己预算三类子结构；仿真批次与目标达成结果由仿真模块产生；账户分配由价值分层账户模块产生；风险容量逐月记录由风险容量模块产生；二选一方案由多目标优化模块产生；术语解释由术语模块产生；决策历史由成长护照模块产生，属可选功能。

| 实体 | 关键字段 | 主要约束 |
| --- | --- | --- |
| 模型参数 | 序号、名称、基准取值、悲观档、乐观档、单位、来源、年份样本、性质、备注 | 三档取值须递增；假设类与惯例类必填三档 |
| 用户画像 | 画像标识、年级、月生活费、增长率、现有积蓄、风险偏好、仿真时长、次数、随机种子 | 月生活费大于零；增长率在零至零点一之间；现有积蓄非负 |
| 收入来源 | 类别、启用开关、参与概率、金额区间、起止月份、中断概率 | 除生活费外，每类均须支持概率为零的极端情景 |
| 人生目标 | 目标标识、名称、金额、到期月份、优先级 | 数量一至五；到期月份落在仿真区间内；优先级即录入顺序，取值不小于一，随拖拽调整同步重排 |
| 悦己预算 | 成长悦己上限、体验悦己上限 | 非负，允许为零 |
| 仿真批次 | 批次标识、画像标识、种子、时长、次数、生成时刻 | 外键指向用户画像 |
| 目标达成结果 | 目标标识、达成概率、首次达成月份分位、缺口、断流路径数 | 概率落在零至一之间 |
| 账户分配 | 月份、账户、当月分配额、累计余额、缺口 | 同月四账户分配额之和等于当月可用资金 |
| 风险容量记录 | 月份、安全垫厚度、目标刚性、收入变异系数、原始分、等级、权益上限 | 等级由安全垫厚度分档并接受刚性修正 |
| 二选一方案 | 方案标识、目标标识、方案类型、调整后预算、差额、延后月数、可行标志 | 可行标志为假时数值字段为空 |
| 决策历史 | 记录标识、批次标识、所选方案、决策时刻、结论摘要 | 属可选功能 |
| 术语语料 | 文档标识、类别、标题、获取地址、获取日期、正文路径 | 标题须含产品全称，来源须可追溯 |
| 术语解释 | 术语、三层文本、关联目标、是否含数字、生成路径、免责提示 | 关联目标为空时不得包含数字 |

### （三）索引策略

文件存储没有数据库索引，但同样的访问模式需要等价手段。按参数性质筛选使用二级索引，载入时按性质分组为字典；按画像取最近一次仿真使用主键加指针；按目标取达成结果使用哈希索引，以目标标识为键组织为字典；按月取账户余额使用聚簇索引，时间轴天然有序，按月份下标直接定位；按术语检索语料使用倒排索引，维护术语与别名到文档段落的映射。

其中倒排索引需要特别说明：术语检索要求支持近义词匹配，单纯的关键词倒排不足以覆盖，需要在索引构建阶段为每个术语维护别名列表，检索时先做别名归一化再查表。

### （四）数据校验规则

校验分三个层次。字段级校验概率与比率类字段取值区间、金额类字段非负、月序类字段为正整数且不超出仿真时长、枚举类字段只能取定义值、三个取值须满足递增关系。实体级校验目标数量、仿真时长与次数为正整数、三档取值齐备性由性质决定、方案可行标志与数值字段互斥。跨实体级校验账户分配守恒、分配优先级、结果完整性、可复现性四类，直接对应四条验收标准。

校验失败时给出中文提示并指明具体字段，程序不得崩溃。错误分类与错误码见接口设计一节。

## 三、接口设计

### （一）设计前提

本产品是单机单进程应用，不存在 HTTP 服务端，因此没有 REST 接口。所谓接口设计在这里指两件事：一是层间契约，即五层之间传递的数据结构与调用约定；二是呈现层调用契约，即界面调用下层时使用的函数签名与错误约定。层间契约是原文档最大的空缺，不定义就无法并行开发，也无法编写单元测试。

### （二）核心数据结构

| 结构 | 用途 | 关键内容 |
| --- | --- | --- |
| 画像结构 | 层与层之间唯一的画像表示，由参数层构造，其余各层只读 | 基础信息、四类收入来源、目标列表、悦己预算、仿真配置 |
| 推演请求与结果 | 推演的输入与输出 | 请求含预算覆盖项与是否复用路径标志；结果含分位带、各目标达成结果、断流月份、三档情景对比 |
| 求解请求与结果 | 反向求解的输入与输出 | 请求含变量名、目标条件、搜索上下界与迭代上限；结果含可行标志、调整后数值、差额、达成概率、延后月数、迭代次数 |
| 账户分配结果 | 四账户的逐月分配与累计余额 | 含分配守恒与优先级两个自检标志，可直接作为验收断言 |
| 风险容量结果 | 当期容量与逐月日历 | 含三项指标、原始分、等级、客观上限、偏好上限与双约束后的最终上限 |
| 术语解释结果 | 三层解释与免责提示 | 含关联目标标识、是否含数字、生成路径与语料来源 |

### （三）接口清单

| 层 | 接口 | 依据 |
| --- | --- | --- |
| 参数层 | 载入参数、载入画像、校验画像、保存画像 | 数据需求与输入校验相关功能需求 |
| 仿真层 | 推演现金流、评估目标达成、情景对比、生成容量日历、释放缓存路径 | 收入与支出建模、达成概率、情景对比、容量日历 |
| 决策层 | 分配账户资金、测算风险容量、求解二选一方案、应用方案并重算 | 资金分配、容量测算、二选一方案、方案重算 |
| 解释层 | 检索语料、生成三层解释、取免责文案 | 术语检索、三层解释、免责提示 |

### （四）错误码体系

采用三段式：层、类别、序号。层取参数层、仿真层、决策层、解释层、呈现层；类别取输入校验、数据缺失、计算异常、资源、外部依赖、无解或不可行。

| 错误码 | 触发条件 | 用户可见文案 |
| --- | --- | --- |
| P-01-01 | 画像字段超出允许区间 | 月生活费必须大于零，请检查该字段 |
| P-01-03 | 到期月份超出仿真时长 | 目标的到期月份超出了当前的推演范围，请调整月份或延长推演时长 |
| P-02-02 | 假设类参数缺少三档取值 | 参数缺少情景取值，无法进行三档对比 |
| S-03-02 | 数值溢出或出现非有限值 | 当前参数下推演结果异常，请检查金额区间设置 |
| S-04-01 | 内存不足 | 推演所需内存不足，可尝试减少仿真次数 |
| D-06-01 | 二选一方案无可行解 | 即便把体验悦己预算降到零，该目标仍需顺延约若干个月 |
| E-02-01 | 语料检索无结果 | 暂时没有收录这个说法，可以换一个词试试 |
| E-05-01 | 外部模型不可用 | 已切换到本地解释模式，内容可能略有不同 |
| V-04-01 | 推演进行中用户重复触发 | 正在推演，请稍候 |

错误提示统一要求：使用中文、指明具体字段或原因、不暴露堆栈信息、程序不崩溃。

### （五）不变量

以下不变量在每次调用后都应成立，建议作为单元测试的断言集合：同一画像与同一种子两次推演的达成概率完全一致；任意月份的四个账户分配额之和等于当月可用资金；安全底座未填满时长期复利与体验悦己的当月分配为零；任意账户余额不为负；每条目标都有对应的达成结果且概率落在零至一之间；求解过程全程复用同一批随机路径；解释结果中的目标标识为空时第三层不含数字；任何输出都附带免责提示。

## 四、界面与交互设计

### （一）整体结构

界面采用三页结构，默认进入第一页。第一页为看见结论，是核心展示区，自上而下依次为定位条、推演五步说明、结论层、图表层、决策层、假设面板与反事实面板；第二页为我的情况，承担录入与校验并提供月度结余预览，入口由页签降为定位条上的按钮；第三页为全部词条，保留术语检索备查。解释不再独占入口，改为就地触发层：结论与图表里出现的专业词与产品自造词带虚线下划线，点击即在原地展开三层，不离开当前页面。顶部为产品标识区，含产品名称与产品标识。底部常驻月度可用结余条。

这样安排的理由是：用户任务链是「看到结论—改成自己的情况—调整预算—再看结论」，在录入与推演之间反复往返，把录入设为默认入口会要求用户先填完空表才肯展示能力。默认进入结论页，则系统在开场三十秒内就回答了「这东西对我有什么用」。

### （二）设计系统

色彩。主色为银行红，深色用于强调，浅色用于区间填充，最浅色用于提示底色；中性色由正文色到分隔色构成九级灰阶。四个账户各占一色并在全部图表中保持一致：安全底座用深酒红，成长悦己用砖红，长期复利用墨绿，体验悦己用琥珀。同类含义在不同图表中必须使用同一颜色。

字型。分三个角色。结论层的三句大字使用衬线体，取银行文书式的庄重感，这是整套界面里唯一做到极致的细节。正文与控件使用无衬线体。数字统一使用等宽体并启用等宽数字特性，保证表格与图表中的数字纵向对齐。

间距与圆角。卡片圆角十四像素，控件圆角六像素，输入框内边距八像素乘十像素，卡片内边距二十像素乘二十二像素，区块间距二十四像素。

信息密度。本产品属于数据密集型工具，不适用少一层容器、少一个图标的克制策略。每页保证至少三处产品差异化信息：第一页有月度结余实时预览、参数性质标注与应急金目标；第二页有三句结论、四张图表与二选一方案的量化数字；第三页有跨层关联的目标名称与免责提示。

### （四）原型实现

原型为单文件网页，无外部依赖，双击即可离线运行，满足可本地运行的交互原型这一交付形态要求。三页全部可切换；第一页支持目标增删与实时结余预览；四张图表由真实仿真结果驱动，参数取自需求文档附录；点击二选一方案会以新预算重算全部图表；术语解释的第三层以当前画像的首要目标落数并交代其余目标，目标缺失时自动转为固定合规文案。

多目标的一致性由一处次序统一保证：目标按优先级排列，图例、目标概率图、三档情景表、结论层的其余目标一行、解读要点与反事实面板全部取自同一份次序。反事实面板一次扰动即取出全部目标的概率，界面可按目标切换，切换不重新计算。

| 图表 | 内容 | 数据来源 |
| --- | --- | --- |
| 现金流分位带 | 百分位十、五十、九十三条曲线构成的区间带 | 仿真层逐月余额分位数 |

## 五、设计评审

### （一）总体结论

四项设计均已完成且相互自洽：架构设计确定了分层单体的选型与跨层调用的例外约定，数据设计确定了十三类实体与文件存储方案，接口设计冻结了三组核心数据结构与四层接口，界面设计给出了完整的设计系统与可运行原型。

设计过程中共发现十项原需求未决问题，其中两项属于需求内部矛盾，必须在原文档下一版本中修订，否则实现时只能由开发人员自行解释。

### （四）评审结论与下一步

四项设计在可行性、完整性、与需求一致性三个维度均达到可进入实现的程度。主要遗留风险不在设计本身，而在需求侧仍有十项未决问题，其中三项属于阻断级。这三项在本次设计中都已给出具体取值或实现方式，但需要需求方确认后才能作为正式口径。

下一步建议按以下顺序推进：先确认三项阻断级问题；再按数据设计建立参数文件并补齐三档取值；随后冻结三组核心数据结构，进入分模块实现。
