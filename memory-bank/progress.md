### 前后端开发（同日续二）

按需求侧审查、系统设计两块共九个子项推进之后，进入实现阶段。

**领域计算**

实现仿真、分配、容量、求解、解释五个模块。仿真层把余额递推 b_t = max(0, b_(t-1) + n_t) 改写为「累积和减去历史最低点」的等价形式，一万条路径乘九十六个月可整体向量化；随机路径一次生成后按画像指纹缓存，供反向求解反复复用。方案一求的是可行上界而非最小值——预算越低储蓄越多、达成概率单调上升，所以「能达标的最小预算」恒等于零，有意义的是反面：在不放弃按期达成的前提下最多还能花多少体验悦己预算。

**接口与界面**

接口分目录、画像、推演、方案、术语五组。前端为原生脚本，三个页签与四张手绘 SVG 图表，数据全部来自接口。

**子智能体评审**

三个子智能体并行独立评审——后端算法、安全、前后端契约。评审发现中真正会算出错数的三处：

1. 随机路径缓存的键漏掉突发支出参数与刚需占比，改参数后缓存仍然命中，静默使用旧值。
2. 达成月份分位被系统性抬高。原实现把未达成路径记成推演期末再取中位数，导致达成比例低于分位点时中位数恒等于最后一个月。
3. 前端实习来源缺金额上限字段，参与期望计算时得到空值，默认画像一打开结余条即显示告警。

安全侧没有可直接利用的漏洞。补了计算量上限、上下文逐字段清洗、内容安全策略与主机校验。

**评审之外新发现的建模缺口**

初始余额此前没有落地。所有画像从零余额起算，于是「有积蓄的考研型学生」被算成完全没有安全垫，容量等级拉不开差距。补上该字段后三份画像的容量等级才分化。

### 数据库驱动重构（同日续三）

按三条新增要求重构：产品中不得出现赛事内容；目录按前端、后端、数据库、文档分层；所有业务数据必须来自数据库并由接口提供增删改查，枚举与字典类固定数据同样入库。

**数据层**

建立十七张表，分字典、配置、参数与来源、文案、业务实体五类。业务数据以十二份种子文件为唯一来源，首次启动自动建库导入。字典项的属性字段承担了可扩展性：收入来源类别在字典里声明自己的分布形态与可填字段，新增一类收入来源只需加一条记录，前后端都不改代码。

**分层**

后端分接口、应用、领域、数据访问四层。领域层为纯计算，全部系数以配置对象注入，函数签名里没有业务默认值；该层不读文件、不连数据库、不发网络请求。接口层不含业务规则也不接触数据库。前端不含任何可见文案与业务取值。

**新增的守门测试**

数据一致性检查会扫描后端与前端代码，把种子文件里所有有辨识度的业务取值逐个拿去搜索，任何一处出现都判为硬编码；同时校验前端引用的每个文案键、字典类型、配置键、参数键在数据库里真实存在。

**重构中挖出并修掉的问题**

1. 刚需占比同时写在参数表与配置表，领域层读的是配置表，导致改参数表不影响结果。现已定死分工：带来源与性质的业务参数只放参数表，引擎阈值与权重只放配置表。
2. 静态分析自动修复把 sqlite3.Row 的 keys() 改成直接迭代，而该对象迭代出的是值不是键，直接抛下标错误。已改回并加注释豁免。这类自动修复必须逐条复核。
3. 画像在库里把悦己预算拆成两列，对外却是嵌套结构，导致创建画像时非空约束失败。现读写两端各做一次结构映射。
4. 静态资源路由只允许一级路径，assets 目录下的样式与脚本全部取不到。改为解析后校验是否仍在前端目录内。
5. 前端新建目标的默认金额是硬编码的，已挪进配置表。

**赛事内容归口**

产品代码、界面文案、种子数据与目录命名中不再出现赛事字样，全部集中到 docs/交付说明.md。

### 智能体接入与收尾（第五轮）

用户要求完成全部开发，不留未完成与占位。

**智能体能力**

引入 `backend/agents/`。定义入库（agents、agent_tools、agent_bindings 三张表），代码只提供执行引擎：工具处理器、本地渲染器、以及把两者串起来的运行时。

一次调用固定为三段——前置工具、生成文本、合规校验，每段都留下一条可追溯的步骤记录。必需工具失败或必需校验不通过时整体失败，绝不把半成品交给调用方。

两个智能体：术语三层解释与结论解读。六个工具：语料检索、推演摘要提取、情景对比提取、账户分配提取、金额与月数格式化、合规校验。

生成有两条路径。rule 是本地确定性渲染，不联网；openai_compat 调用 OpenAI 兼容接口，任何环节失败都回落到 rule 并在响应中标记降级。两道闸门——全局是否允许联网、该智能体是否被指定为本地规则——都放行且地址与模型名齐备时才发出网络请求。配置缺失一律报错，不回落代码里的默认值。

术语接口改为委托给同一个智能体。两条入口共用一条链路，也就不会出现结果不一致。

**排查出的缺口与处理**

1. 术语语料三份是结构模板，正文标着待补 → 替换为按公开披露制度与现行制度整理的要点，并明确标注为要素整理而非原文引用，登记来源与获取日期。
2. `explain.provider` 与 `explain.allow_external_model` 是名不副实的开关，打开不产生任何网络调用却会把本地产物标为模型生成 → 随智能体配置组一并移除。
3. 契约里写明用于回写提示的断流月份，前端从未消费 → 结论层增加断流回写，展示月次、涉及路径与代表性月份。
4. 目标缺口返回的是下划线命名，与其余字段的驼峰约定不一致，前端也从不渲染 → 序列化时统一命名，并在目标图表下方展示。
5. 数据库文件损坏时抛的是 DatabaseError，原实现只捕获 OperationalError，异常会穿透到启动阶段 → 覆盖该情形，把损坏文件改名留存后重建。
6. 接口层两处内联 SQL 违反分层约定 → 收回仓储层。
7. `_integer` 对浮点入参静默截断，使用者会以为自己填的数字生效了 → 明确要求整数并给出中文提示。
8. 未使用的配置项、前端导出函数、文案条目 → 清理，并补上反向检查：每条界面文案与提示文案都必须被某处引用，避免死文案复发。

**过程中发现的一个真实缺陷**

账户分配顺序。长期复利没有上限，它一旦排在体验悦己之前就会吸走全部剩余资金，使体验悦己预算这一输入项完全失效——这正是决策 D-15 要修正的问题。但账户表的优先级定义从未跟着改，实现里体验悦己恒为零。

这个缺陷此前一直没被发现，原因是：账户堆叠图里那一条始终为零不会报错，界面上也没有任何断言。它是被一次端到端冒烟中的账户顺序字符串暴露出来的。已把优先级调整为安全底座、成长悦己、体验悦己、长期复利，并补了回归测试。

**自检**

测试全部通过，静态分析无告警，前端语法与元素引用检查通过。三个页面与全部接口端到端跑通，路径穿越与主机校验按预期拒绝。

### 收支分离重构（第八轮）

用户指出产品「像玩具」：支出不可配置、年级脱钩、参数黑盒。据此做了收支分离重构，这是对建模的根本修正。

**核心变化**

删除「刚需占比」这一把支出写死的参数。收入流与支出项彻底分离：

- 收入流：家庭支持、兼职、奖学金、实习、助研助教，可增删，年级驱动默认窗口。
- 支出项：房租、餐饮、交通、日用品、通讯（刚需）、学习、社交、娱乐（弹性），逐项配置金额、刚需标记与独立增长率。
- 结余 = 收入 − 支出，逐月模拟。

**修复的深层缺陷**

成长悦己此前被双重处理——推演里当支出扣掉，账户分配里又当上限，同一笔钱算了两次。现在只在账户分配里作为上限，支出侧只剩真正的支出项。

**年级驱动**

年级字典新增收入窗口映射。前端选择年级时自动调整各收入来源的启用状态与时间窗口，消除「研一却选大三实习型」的矛盾。画像名同步去除年级绑定，「大三实习型」改为「实习成长型」。

**参数透明**

配置目录新增参数完整行，录入页展示每个假设参数的值、性质（实测/假设/惯例）与来源。

**缓存键修正**

随机路径缓存键此前不含支出项，改动支出会命中旧结果。已把支出项纳入指纹。

### 画像重构（第九轮）

用户指出「画像设计得不行」。据此把画像从生涯路线标签重构为财务状态。

**核心变化**

三份画像按财务维度重命名：多元收入型、高刚需型、长期积累型。名字、摘要、要点全部改为财务叙事，不再出现实习、考研、考公这类生涯词。

画像不再绑定年级。加载内置画像时保留用户当前选择的年级，随后按年级重算实习、助研等收入的时间窗口，消除「研一却挂着大三窗口」的错位。年级仅作为推演兜底值留在画像数据里。

**新增用户档案**。archetypes 表加 kind 列（builtin / user）。用户可以把当前配置保存为本地多份档案，随时加载、删除；内置画像不可删除。前端画像下拉分两组展示。

**校准过程中发现并修掉的数字问题**

1. 原考研型画像月结余约一百四十元，却要在十二个月里攒一万八，加载出来达成率必然是个位数。重构后高刚需型主目标达成率百分之三十五点五。
2. 次要目标金额等于初始余额时，目标在第 1 个月就「达成」，属于伪达成。已把目标金额提高到高于初始余额。
3. 长期积累型月结余太薄（约二百一十七元），远期目标必然失败。已把月结余调到约四百五十元，三个目标达成率落在五十七到六十之间。
4. 三份画像主目标达成率最终为：多元收入型 65%、高刚需型 36%、长期积累型 58%，有明确区分度。

**防回归**：新增两条测试——内置画像不可删除；三份画像主目标达成率必须在百分之三十到八十五之间。

### 城市生活成本系数（第十一轮）

用户要求「不要死字段，要有影响」。城市字段此前零影响，现已落地：

- 城市改为字典下拉，八个城市各带生活成本系数（北京 1.30 至郑州 0.85，全国基准 1.00）。
