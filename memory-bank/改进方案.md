# 改进方案：从能跑通的原型到可交付的产品

> 本文件记录对当前实现的一轮整体反思与改进设计。写作前提是项目负责人的六点批评：像玩具、没法交付；功能对自己的解释不清晰；画像录入不够灵活、无法适应灵活场景；面向的用户不清晰；沙盘推演看不懂、不知道怎么推演；推演数据看不懂；术语解释涉及术语不多且与前两项功能无关联。
> 本文件只做方案，不改动代码。落地顺序见第七节。

## 一、问题的统一诊断

六点批评不是六个毛病，是同一个毛病从六处冒出来：**系统按自己的内部结构组织，而不是按用户的任务组织。** 我把根因收拢到四条，每条都落到一个具体的产品决策上。

### （一）核心承诺是两个并列数字，不是一个决定

现行定位写的是"把结果翻译成两句与用户个人直接相关的话"。目标推迟多久来自预算求解，能承受多大波动来自安全垫厚度，两者之间没有取舍关系。用户读完没有任何必须去做的事，这就必然读作玩具。

### （二）最强的那件东西被自造术语锁住

我手上真正稀缺的资产是"一笔当下开销等价于目标晚多久"，以及"在不放弃目标的前提下每月还能机动花多少"。但这两条结论在界面上的主语是"压缩体验悦己预算，按期达成"——安全底座、成长悦己、体验悦己、长期复利是对内正确的账户名，对外是黑话。用户拿到的不是一个可执行的金额，是一个内部变量名。

### （三）入口要求用户先具备财务自我认知

画像已从生涯路线改为财务状态，方向对，但没解决根本问题：三份内置画像要求用户先判断自己属于哪种财务状态，再逐项填收入流、支出项、目标金额、悦己预算。这等于要求一个从未记过账的人先做一次记账才能使用，而产品边界又明令禁止我做记账工具，于是这道门槛没有任何东西替用户跨过去。"不够灵活"的真相在这里：默认路径假设用户已经把自己的钱想清楚了，而产品存在的理由恰恰是他没想清楚。

### （四）没有"用完之后"的画面

一百三十七项测试证明的是实现自洽，没有一项证明用户看懂了。流程终止于图表刷新，用户什么也没带走。

## 二、产品定位与用户收敛

### （一）用户表失焦的两处

其一，把"现场观众"写进了目标用户表。观众不是用户，是评审场景的约束。一旦把它列为第三类用户，就等于承认产品有一部分是为"看起来厉害"而设计的，不清晰正是从这里散发的。

其二，分类轴落在生涯阶段而非决策处境。在校生与职场新人的财务结构几乎同构——收入不稳、储蓄薄、近期有刚性支出，差异应降为默认参数差异，由城市系数与收入来源开关承担，不再作为两套用户模型。

| 处理 | 内容 |
| --- | --- |
| 收敛为单一第一用户 | 二十二至二十八岁，收入不稳或刚转稳，近三年有一笔金额明确的刚性目标（考研自筹、租房押金、进修、首付的一部分），且答不上"我每月能安全花多少"的人 |
| 校生与新人的差异 | 降为默认参数差异 |
| 演示受众 | 移出用户表，改列为演示约束：一条完整链路须在三分钟内讲完 |

### （二）定位句重构

**改写版本**：给收入不稳定的年轻人，把"这笔钱花不花"翻译成"那个目标会晚多久"，再把两个都说得通的取舍摆出来，由你自己挑。

好在三处：主语从系统换成用户的认知转换，用户买的是换算而不是仿真；产出从"两句话"变成"一个数字加一个必须做的取舍"，前者读完即止，后者必然导向一个动作，而这个动作就是演示的高潮；它顺手守住了边界——不替你决定，也不推荐任何产品，把五条硬约束变成卖点而非免责声明。

### （三）支撑演示的完整用户故事

周晨，二十三岁，研二。每月家庭支持两千五，助研津贴学期内一千二、寒暑假归零，偶尔接项目进账三到六千。她想去明年八月赴英交换，需自筹四万。她此刻卡住的不是四万，是一个更小的东西：今年能不能放心每月八百去看演出和聚餐，要不要现在花六千八报雅思冲刺班。

她打开软件，不先选画像，只回答三问（在校还是校外租房、每月大致能剩多少、最放不下哪个目标），系统生成一份草稿画像，她只改了两处数字。推演后她看到三句结论：这个目标按期达成的可能性不到一半；中位情形要顺延七个月，正好错过申请截止；在当前开销下，明年的她是脆的。方案区给出互斥两条——维持八百的机动开销，交换延后九个月；或把机动开销压到四百八十，按期出发。

她把四百八十这个数记了下来。走出去时她不再纠结"我该不该省"，而是知道"未来十二个月里每月可以花四百八十而不影响明年八月"。演示的落点就是这个具体的数字。

## 三、信息架构重构

### （一）并列页签的问题

三个页签按模块切：录入是输入、沙盘是输出、术语是解释。三者语义并不平级却被摆成同级，"查阅解释"因此被抬到与"看结论"同等的地位——这正是术语关联缺失的成因。

页签上的 01、02、03 还制造了一次流程谎言。它暗示线性顺序，但真正的用户任务链是"看到结论 → 改成自己的情况 → 调整预算 → 再看结论"，在录入与沙盘之间反复往返。并列页签把这条往返链压成了单向通道。

更直接的证据在初始化逻辑：`DOMContentLoaded` 之后强制激活录入页，而初始化过程中已经静默跑完一次完整推演，结果算出来后闲置不用。系统先要求用户填完空表，才肯展示自己能做什么。

### （二）重构后的四个区域

| 区域 | 定位 | 与现结构的关系 |
| --- | --- | --- |
| S1 看见 | 首屏即结论。载入默认画像直接出三句结论 | 由沙盘页结论层独立升级 |
| S2 调整 | 我的情况。仅在用户要换成自己的数据时进入，定位是"改"不是"填" | 原画像录入页，入口由页签降为按钮 |
| S3 取舍 | 结论层、四张图、二选一方案 | 原沙盘页其余部分 |
| L 解释层 | 覆盖式就地解释，非页面 | 原术语页签升级为全局触发层 |

流转：默认进入 S1 → 点"换成我的情况"进 S2 → 保存即回 S3 → 任意专业词就地唤起 L。

这样安排的理由有三：任务动线收敛成一条；解释层永远携带当前推演快照，第三层自然能用用户自己的目标与推迟月数说话；它天然容纳术语的就地化改造——术语三张表、术语接口与智能体链路全部不动，只把入口从页签改为触发器，领域层与表结构零改动。

### （三）首屏三十秒

首屏由三块构成：定位条（对谁、做什么、明确不做什么）、三句结论（达成可能性、预计延后、风险容量）、合规条。底部常驻结余条，顶部给一个"这是示例数据，换成我的情况"的按钮，把录入从义务变成选项。

第二块是推演过程的可见化，结论层下挂一个可折叠的五步说明：抽样收入与突发支出路径 → 逐月余额递推 → 判定各目标达成月份 → 按四账户优先级分配 → 容量按客观与主观双约束取严。这一步同时回应两条批评："不知道它怎么推演的"，以及"代码计算的会不会缺失灵活性"——后者并不要求改算法，而是要在界面上把参数表暴露出来，说明随机性来自抽样、确定性来自入库参数、灵活性来自参数可编辑，由此把"写死的代码"重述为"参数驱动的可复现计算"。

## 四、画像录入：从填表到改一份草稿

### （一）三个层面的具体诊断

字段层，问题在于"不填"被静默转译成"零"。前端取空值得零，后端对空值一律返回默认零，于是"不知道有没有奖学金"与"奖学金为零"在推演中等价。更严重的是家庭支持存在硬性大于零的校验，一个不再向家里要钱的用户连第一步都过不去。兼职参与概率、实习中断概率这些字段必填且缺省为零，而概率零在引擎里的语义是"永不发生"，不是"不确定"——用户给出最诚实的回答，系统把它当成否定。

交互层，界面开局即摆出约三十个已填好的输入框，数值取自字典默认值与城市系数。这套默认值看着专业，实为"精确但错"；用户以为不填即跳过，实际全部照默认执行。此外家庭支持存在两个入口且单向同步，改左随右、改右不动，这不是清晰性而是困惑。

数据模型层，所谓"收入流可增删"事实上只对目标成立——收入与支出分区遍历字典全量渲染，既无新建入口也无删除入口，收入五类、支出八类固定。真实的第六类收入只能借壳"兼职"，名字还改不了。

| 层 | 约束 | 后果 |
| --- | --- | --- |
| 年级 | 取值须落在年级字典 | 已工作、休学、延毕、间隔年只能伪装 |
| 收入来源 | 金额为月额，时间为起止窗口 | 一次性、季节性、按项目结算只能摊平 |
| 支出项 | 单调增长、无期限、无月份乘子 | 助学贷款"还完即止"、寒暑假结构差异无法表达 |
| 年级驱动窗口 | 终止月份写死九十六 | 推演可至一百二十月，收入却在第九十六月凭空中断 |

### （二）当前模型覆盖不到的场景

| 场景 | 卡在哪里 |
| --- | --- |
| 已工作、有年终奖 | 无薪资类；一次性收入仅按概率摊平，到账月份被抹平 |
| 自由职业按项目结算 | 逐月独立命中表达不了"约每季一笔"的频率相关 |
| 考研二战、无收入 | 家庭支持大于零的硬校验无法通过 |
| 与伴侣分担房租 | 房租只有绝对额，无份额概念，用户心算一半再填，模型里不留痕迹 |
| 助学贷款还款 | 无负债主体；支出有增长无终止，还完不清零 |
| 寒暑假 | 支出为固定月额加复利增长，无月份乘子、无校历概念 |
| 一次性大额收入 | 分段语义仅属实习与助研，且仍是月额 |

### （三）改进方案

取舍原则只有一条：**不增加必填项，只在语义上做文章。**

降低门槛四条：

1. 三问起步——身份处境、所在城市、每月大致可支配金额，据此生成草稿写入现有表单，其余全部可改。
2. 以"人生阶段"取代年级——在读本科、在读研究生、已工作、间隔年与备考、其他。字典驱动是既有机制，此处只增数据行，不动表结构。
3. 允许留空与"不确定"——把家庭支持校验改为"启用收入合计大于零"；每类收入加确定、大致、不知道三态，未知时以同城同阶段中位数兜底，并在结果页标注该字段为估算。我宁愿让用户在知情的情况下被估算，也不愿他在不知情时被默认值代表。
4. 默认值由"精确但错"降级为"模糊但可改"——保留字典默认，以浅色加"估算"角标呈现，允许一键清空。

提高表达力两条：为收入增加"节奏"语义（每月、每年一次、一次性、按项目），控件不新增，复用既有起止月份，一次性时令起止相同，每年一次仅追加"常在几月"一项；周期性差异用十二元月度乘子向量表达，默认全一，勾选"在校模式"即对餐饮、交通在假期月份套乘子。

缺失数据统一三层兜底：用户输入优先；无输入取同城同阶段中位；仍无则以区间参与仿真，把不确定性呈现为结果的离散度，而不是假装不存在。

## 五、推演沙盘：从一堆数字到可行动的结论

### （一）输出的四层结构

| 层级 | 承载内容 | 用户在此解决的问题 |
| --- | --- | --- |
| 第一层　一句话结论 | 首要目标能否按期达成、不能的话差什么 | 我该不该担心 |
| 第二层　三个关键数字 | 达成可能性、预计延后、容量上限，每个数字附一句人话注解与一句行动 | 差多少、动哪里 |
| 第三层　支撑证据 | 四张图、断流月份、缺口清单 | 凭什么这么说 |
| 第四层　可追溯的假设 | 参数名、取值、性质、来源与统计期间 | 这些假设我认不认 |

第四层目前完全缺失，而它是回应"凭什么"质疑的唯一通道。参数表里每个参数都已带性质标记、来源与统计期间，数据基础已经在库里，只是从未走到界面上。

### （二）数字翻译成人话

翻译原则是：概率换算成"一百个未来里有几个"，等级换算成"允许你做什么"，金额换算成"每月少花多少"。

| 原始输出 | 现在呈现 | 改写 |
| --- | --- | --- |
| 达成概率 0.43 | 43% | 一百种可能的未来里，43 种能按时攒够这笔钱——比抛硬币差一点。想拉到七成，机动开销要从 1200 降到 850 |
| 容量等级中、上限 35% | 中 · 35% | 不进账也能撑 3.4 个月。这个厚度允许长期资金最多三成半放进会波动的资产；你填的偏好只允许两成，我按小的取 |
| 延后 6 个月 | 6 月 | 多半不是攒不够，是攒晚了：大约第 31 个月才够，比你要的第 25 个月晚半年 |
| 断流 68%、缺口 137 | 裸数字并列 | 68% 的可能会撞上至少一个月钱不够，最危险的是第 14、15、26 个月——都是开学与换季的位置 |

第二层的三个数字我都要求配一句行动。容量等级尤其需要：单独给出"中"没有任何决策含义，只有翻译成"允许你把多少比例放进波动资产"，它才变成一个可执行的数。

### （三）让过程被看见

我不打算把机制写进界面，而是用三件东西让用户自己看见过程。

**五步时间线**：每步一句白话加一句输入说明。第二步的断流规则与第四步的账户顺序，正是最容易被质疑、也最值得公开的两处。

**单条路径的具象化**：余额矩阵已完整保留，前端却只用了分位序列。取出三条代表路径（贴近 p10、p50、p90 的期末余额），以事件卡形式讲一段话——"如果你这三年是这样过的：前 13 个月兼职不断，第 14 个月一笔 1800 的意外支出把余额清零，第 19 个月拿到奖学金，第 31 个月攒够目标"。三条并排，用户立刻明白概率不是抽象数字，而是这一类未来长这样。

**反事实与敏感性**：现有三档情景只缩放收入，支出与突发支出不动，且只输出一个百分数。改为可操作的反事实面板：选定参数，拖动取值，实时回写首要目标达成概率的变化幅度，并用一张龙卷风图把所有参数按影响大小排序，直接告诉用户"最值得争论的是哪一个假设"。这一步同时是"结果转化为行动"的落点——排序第一的参数，就是下一步该去核实的那件事。

### （四）回应"代码计算的未来会不会缺失灵活性"

| 怀疑内核 | 现状 | 应对 |
| --- | --- | --- |
| 假设不可查 | 参数来源与性质只在库里 | 第四层假设面板全部陈列，按实测、假设、惯例三色标注，假设类必须显式标记 |
| 参数不可调 | 用户改不了模型参数 | 假设面板内直接改值并重跑。前提是先补齐缓存指纹口径——目前指纹只覆盖画像输入与突发支出三参数，改其他模型参数不会让路径缓存失效 |
| 情景数量有限 | 三档且仅缩放收入 | 改为多因子组合情景加用户自定义情景，支出与突发支出同样参与 |
| 分布形式单一 | 一律均匀分布加伯努利命中 | 明确写出"我假设金额在区间内等可能"，并允许切换为集中于中值的三角分布或锁定为确定值 |

框架上我做一处重塑：把"预测未来"改述为"压力测试"。免责声明从决策区底部提到结论层正下方，改写为——本结果回答的不是"你会怎样"，而是"在什么情况下你的计划会垮，以及垮之前你会先看到什么"。这个改述既符合安全垫与断流的机制本义，也让"假设可调"从缺陷变成特性：压力测试本就该换着条件反复压。

### （五）四张图表的读数问题

| 图 | 当前问题 | 改进 |
| --- | --- | --- |
| 余额分位带 | 分位含义未解释，p10 常被误读为最坏情况 | 图注改为"八成可能的未来落在这一带"；终点标注中位期末余额；断流峰值月份画竖线 |
| 目标达成条 | 颜色分档无图例；条长是概率却被当成攒钱进度 | 加七成参考刻度线；条尾直接标缺口金额；未达成分位显示"期内未达成"而非空白 |
| 四账户堆叠 | 面积是累积余额，读者以为在缩水；最上层无上限吞掉全部剩余 | 提供"累积余额／当月新增"切换，默认当月新增；图注明写最上面一层是剩下的钱 |
| 容量日历 | 纵轴未解释；下探圆点无标注 | 加低于一月的警戒带；圆点注"目标临期，容量下调" |

四张图统一补一句"一句话看点"置于标题下，并把默认高亮对象定死，用户不必自己判断该看哪一处。

## 六、术语解释：从独立词典到就地解释层

### （一）诊断

根子不在"术语"这个概念选错了，而在"把它做成一个入口页"这个信息架构决策。概念本身没问题——年轻人读不懂金融词是真需求；但做成并列页签，等于把解释能力从使用现场抽走，变成一处需要用户主动想起、主动前往、主动输入的地方。术语解释的价值恰恰是即时性：用户在推演结果里看到"容量下探""安全底座未填满"的那一刻才是提问时刻，离开这个时刻，需求衰减为零。

三条事实支撑这个判断：

| 事实 | 说明 |
| --- | --- |
| 库中实际收录五条术语，全部为金融通识词 | 最大回撤、波动率、七日年化、风险等级、赎回费。产品自造词一条都没有 |
| 第三层模板五条各不相同，本地渲染器从未读取 | 无论查哪个词，第三层都套同一句回撤文案，个性化层实为空转 |
| 术语页只依赖推演快照，与画像页零耦合 | 画像录入没有任何一处调用解释能力 |

它真正该服务的需求不是"查词典"，而是"这个系统刚才对我说了什么、凭什么这么说"。解释的对象应当从词语上移到系统输出的一句话。

### （二）重构方案

**保留词表，取消独立入口，把术语改造为就地解释层，并与结论解读合并为同一条链路。** 三条机制，同时回答"为什么画像录入和推演沙盘会用到它"：

1. **就地触发**：录入与沙盘的所有结论性文案（容量等级、待备额、断流、达成概率、四账户名）挂可解释标记，点击就地展开三层，不跳页、不离开当前上下文。
2. **结论解读复用同一链路**：沙盘已有结论解读区块，它与术语解释是同一套三段式、同一批工具、同一道合规校验，仅工具组合不同。二者归一为一个解释智能体，以类型分派渲染器，术语解释成为结论解读的子能力而非平行功能。
3. **画像侧的解释由录入动作驱动**：录入完成即产出一条"你的画像意味着什么"，把三个财务维度与容量等级讲明白，并成为沙盘的入口。

取舍：我放弃了"保留术语页并强化内容"与"只做结论解读、删掉词表"两个方向。前者治不了即时性缺失；后者会让"待备额""断流"这类自造词无处安放，而这些才是用户真正读不懂的东西。代价是术语页要让出一级入口，我认为值得付。

### （三）覆盖面

判断标准三条：该词是否出现在系统输出给用户的文案中；用户是否无法凭字面推断其口径；不解释是否会导致用户误读结论。

| 优先级 | 类别 | 词条 |
| --- | --- | --- |
| P0 | 产品自造词 | 安全底座、成长悦己、体验悦己、长期复利、待备额、断流、容量等级、安全垫月数、容量下探 |
| P0 | 结论口径 | 达成概率、中位达成月、三档情景、分配顺序、资金守恒校验 |
| P1 | 金融通识 | 最大回撤、波动率、风险等级、流动性、定投 |
| P2 | 长尾 | 七日年化、赎回费、业绩比较基准 |

目标二十五至三十条，P0 必须全量覆盖；P2 只作兜底检索，不占界面入口。

### （四）智能体能力的归属

**主战场给结论解读，术语解释作为其薄封装，反事实说明列为二期。**

判据很直接——把某个能力摘掉，产品是否残废。今天摘掉术语页，画像与推演照常跑，产品完整，这正是质疑成立的原因；摘掉结论解读，推演只剩概率数字与曲线，用户读不懂也不敢照做，产品残缺。

同样值得指出的是，三段式里那道合规校验（无目标不得出现数字、不得出现收益承诺、必须附免责）本就是为带数字的结论设计的，用在术语解释上基本空跑，用在反事实说明上才真正发挥——反事实会输出"如果压缩开支会提前几个月"这类新数字，是合规风险最高、最需要机器把关的场景。

让它成为产品必需还需一步：把解释结果接回动作。结论解读的要点应当可点击——"调整目标到期时间"直接跳到沙盘的对应控件，"压缩非必要开支"直接触发方案重算。解释一旦通向下一步操作，就不再是装饰。

## 八、不做清单

我不做用户系统、登录与云同步，与"运行数据不落盘"冲突；不做新的推演模型，现有蒙特卡洛加二分求解已满足全部验收；不做记账、流水导入与账单解析，属产品边界明令排除；不做移动端适配，演示环境是笔记本；不新增第五张图，不做缩放导出等交互升级；不把术语条数扩张到几十条，改为覆盖界面用词加就地触发；不引入前端框架，分层边界依赖它；不改账户分配顺序与目标达成口径，两项已挂待确认，改动会推翻既有决策与校准过的演示数据。

录入侧明确不做：多主体合租分摊、负债摊销与利息、税务计算——这三项需要重构引擎与账户层，超出竞赛范围。

## 九、风险与测试防线

会动到表结构的三处：术语就地触发若需要"术语—界面元素"绑定关系会新增表；三问草稿若引入新字段会动画像结构；参数面板需确认参数表三档字段可直接读取。会动到领域层的一处：五步说明要暴露路径数、断流率、分位等中间量，会改动推演响应结构，接口契约与断言需同步。

守住现有测试的作法是四条：响应结构只加字段、不改字段；领域层纯函数签名不动，中间量作为新增可选输出；表结构变更一律走增量脚本，不重建既有表；每批改动后跑测试、静态分析与语法检查三道。数据一致性检查会拦截硬编码业务取值与未被引用的死文案——新增文案必须同步入库，否则反向校验直接转红。

第一至五项完成后，我建议冻结领域层，此后只动文案与样式，把回归面收窄到数据层。
