# 技术栈

## 一、实现后的实际选型

| 层次 | 组件 | 实际选型 | 说明 |
| --- | --- | --- | --- |
| 语言 | 运行时 | Python 3.11 及以上 | 生态完整，数值库成熟 |
| 服务 | Web 框架 | Flask 3 | 单进程，只监听本机回环地址 |
| 仿真 | 数值计算 | NumPy | 路径生成与逐月递推整体向量化 |
| 存储 | 数据库 | SQLite（标准库 sqlite3） | 单文件嵌入式，无独立进程 |
| 界面 | 页面 | 原生 HTML 与 JavaScript，无框架、无构建工具 | 三个页签、四张图表，一次接口往返完成初始化 |
| 界面 | 图表 | 手写 SVG | 不引入图表库，配色与坐标由数据库下发的账户定义驱动 |
| 参数 | 配置 | 数据库表 | 带来源与性质的业务参数在参数表，引擎阈值与权重在配置表 |
| 测试 | 单元与接口 | pytest | 分领域、接口、数据三组 |
| 测试 | 静态分析 | ruff | 含安全规则集 |

依赖清单只有四项：Flask、numpy、pytest、ruff。

## 二、与原推荐的偏离及原因

设计阶段曾推荐 Streamlit 加 Plotly 的单机桌面方案，实现阶段全部推翻。三处偏离都需要留档：架构与数据文档已按实现结果改写，若不说明依据，本文件的选型会显得凭空出现。

**偏离一：界面框架由 Streamlit 改为原生前端加 Flask。**

原推荐的依据是需求文档 8.1 节「界面采用轻量框架，开发人员无需具备前端开发能力」。推翻的理由是后续增加的产品要求：业务数据必须由后端接口提供、前端不得承担任何业务计算与硬编码。这两条需要一条真实的接口边界，而服务端渲染的框架里这条边界是软的，无法用静态检查守住「前端不含业务量」这条约束。改为原生前端后，前后端之间的契约变成了可校验的接口，测试可以直接扫描页面与脚本确认没有残留业务取值。

**偏离二：图表由 Plotly 改为手写 SVG。**

图表数量固定为四张（分位带、目标概率、账户堆叠面积、容量日历），类型固定，交互只有悬停提示。引入图表库带来的体积与依赖成本高于收益，且账户配色需要按数据库里的账户定义动态生成，手写反而更直接。

**偏离三：参数由 CSV 与 TOML 改为数据库表。**

原推荐的依据是「参数需要人工编辑并核对来源，纯文本文件可直接用表格软件打开」。推翻的理由是后续增加的产品要求：所有业务数据必须来自数据库并通过接口增删改查，枚举与字典类固定数据同样需要入库。改为数据库后，参数编辑通过接口完成，每次写入落变更留痕表，来源与性质作为字段强制填写，这比自由编辑表格更能保证参数表的完整性。

## 三、性能预算的实测结论

| 指标 | 要求 | 实测情况 |
| --- | --- | --- |
| NF-01 单次推演耗时 | 默认参数下不超过三十秒 | 远低于预算。瓶颈不在仿真本身，而在方案一的二分求解，它包含十余次完整重算，靠复用同一批随机路径把总耗时压在一秒量级 |
| NF-02 内存占用 | 不超过两千兆字节 | 实际占用在几十兆字节量级。次数与时长的乘积另设上限，防止单个请求把内存推到不可控 |
| NF-03 结果可复现 | 固定种子时两次运行结果一致 | 随机路径按画像指纹缓存，二次调用直接命中，输出逐位一致 |
| NF-04 界面响应 | 推演期间界面不假死 | 前端异步请求并显示进度提示，服务端对重计算接口加互斥，避免并发推演把内存打满 |

真正吃性能的仍是 M5 的搜索过程，与设计阶段的判断一致。

## 四、生成类功能的形态

术语三层解释与结论解读都由智能体承担，不再是散落在某一个模块里的模板拼装。

一次调用固定为三段：前置工具、生成文本、合规校验。定义（名称、目标、提示词、输出结构、工具绑定、生成方式）全部入库，代码只提供执行引擎——工具处理器、本地渲染器、以及把两者串起来的运行时。

生成有两条路径，对外产出同一套结构：

| | rule | openai_compat |
| --- | --- | --- |
| 是否联网 | 否 | 是 |
| 结果是否确定 | 是 | 否 |
| 需要配置 | 无 | 服务地址、模型名；凭据从环境变量读取，不入库 |
| 失败时 | 不适用 | 自动回到 rule，并在响应中标记降级 |

两道闸门决定走哪条路：全局是否允许联网、以及该智能体是否被指定为本地规则。两道都放行且地址与模型名齐备时才发出网络请求。配置缺失一律报错，不回落代码里的默认值——这与项目对配置的一贯纪律一致。

**产品不依赖外部模型。** 默认配置下全部走本地规则路径，离线可用；接入模型只是为了在语料基础上把措辞写得更自然。需求文档 8.1 节要求的「外部接口不可用时必须降级运行」，在这个结构下是天然成立的，因为降级路径本身就是默认路径。

早前版本中曾有一对名不副实的开关（`explain.provider` 与 `explain.allow_external_model`），打开它们不会产生任何网络调用，却会把模板产物标为模型生成。这两个开关已随智能体配置组一并移除。

## 五、明确不引入的组件

1. 前端框架与构建工具。
2. 图表库。
3. 数据库服务。单机单进程、无并发写入、无远程访问，嵌入式数据库足够，且省掉一个需要单独部署的进程。
4. 容器化与编排工具。
5. 任何行情、交易、征信类外部接口。
6. 任何需要购买或申请授权的数据集。
7. 任何需要付费或需审批的第三方服务。外部模型接口只在显式配置并允许联网时才会被调用，默认关闭，且凭据只从环境变量读取。
