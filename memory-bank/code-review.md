# 代码评审与安全审查报告

评审对象：本次开发的完整实现（后端、前端、数据文件、测试）。
评审方式：三个子智能体并行独立评审——后端业务逻辑、安全审查、前后端契约与交互健壮性。
本报告记录发现项与处理结果，未修复项明确保留原因。

> **阅读提示**：评审发生在数据库驱动重构之前，文中出现的 `app/`、`app/web/`、`app/service.py` 等路径，在重构后分别对应 `backend/`、`frontend/` 与 `backend/services/`。表中列出的问题均已修复或经核实确认无需修改，但代码的组织形态已按后端四层重排。

## 一、后端业务逻辑评审

### （一）已修复

| 编号 | 问题 | 位置 | 处理 |
| --- | --- | --- | --- |
| B1 | 随机路径缓存的键漏覆盖会影响结果的参数。原键只含种子、时长、次数、生活费、收入来源与成长悦己预算，未含突发支出参数与刚需占比，编辑参数文件后仍会命中旧缓存，静默使用旧数值 | `app/service.py` | 键扩展为覆盖 `sudden_freq`、`sudden_low`、`sudden_high`、`need_ratio`；新增回归测试逐项验证参数变化会导致键变化 |
| B2 | `shortfall_paths` 口径错误。原返回「路径乘月份的断流事件总数」，可能远超路径条数，与字段定义不符 | `app/simulation.py` | 改为返回曾出现断流的路径条数；事件总数另立 `deficit_total` 字段 |
| B3 | 达成月份分位被系统性抬高。原把未达成路径一律记为推演期末再取分位，达成比例低于五成时中位数恒为最后一个月 | `app/simulation.py` | 改为在达成分集内取分位并对非达成比例设界，达成比例不足相应分位点时返回空值；界面改为显示「推演期内半数以上路径未达成」 |
| B4 | 断流月份清单无信息量。原取「任一路径断流」的月份，上万条路径下几乎覆盖全部月份 | `app/simulation.py` | 改为按断流路径占比分档，输出 `deficit_months_p10` 与 `deficit_months_p50` |
| B5 | 无法解析的输入被静默替换为默认值。原归一化阶段对非法取值一律回落，校验阶段看到的已是合法值，与「高亮具体字段」的承诺冲突 | `app/validation.py` | 改为显式取值必须可解析，解析失败即抛出携带字段名的校验错误 |
| B6 | 方案一的边界情形不完整。体验悦己预算已为零时，上界回落到 100 元，可能给出正数的「压缩」建议 | `app/planner.py` | 增加预算为零的分支，直接判定为不可行并说明没有可压缩空间 |
| B7 | 首月可分配资金把存量积蓄当成当月新增 | `app/allocation.py`、`app/capacity.py` | 首月可用额扣除初始余额，同时把已持有积蓄计入安全底座起点 |

### （二）核实后未修改

| 编号 | 评审意见 | 结论 |
| --- | --- | --- |
| B8 | 求解器缺少「必须复用随机路径」的硬校验 | 该约束在实现上是结构性保证：求解器接收的是已生成的路径集合而非种子，不具备重新抽样的能力。已在函数文档中写明，不额外引入可被伪造的布尔标志 |

## 二、安全审查

### （一）已修复

| 编号 | 问题 | 严重程度 | 处理 |
| --- | --- | --- | --- |
| S1 | 单一请求即可把内存与计算量推到不可控：仿真次数上限五万、时长的上限一百二十个月均为合法取值，单次推演可达数百兆字节并长时间占用互斥锁 | 中 | 增加「仿真次数乘推演时长」的乘积上限，超限时给出中文提示并指明字段 |
| S2 | 上下文摘要未经清洗即进入下游计算，构造畸形结构会触发未捕获异常并返回 500；异常消息可能带出用户填写的字符串 | 中 | 新增上下文清洗函数逐字段重建结构，非法结构退回无目标文案；异常处理器改为只记录异常类型，不记录消息与请求体 |
| S3 | 缺少内容安全策略与主机校验，域名重绑定可能绕过同源限制读取本地接口 | 中 | 补齐内容安全策略、跨源资源策略，并在请求进入前校验主机名，非本机地址直接拒绝 |

### （二）核实后确认安全

| 编号 | 检查项 | 结论 |
| --- | --- | --- |
| S4 | 静态资源路径穿越 | 现有实现先做文件名与路径一致性校验，再由框架的安全拼接二次拦截，编码、反斜杠、空字节、UNC 路径等构造均无法逃出静态目录 |
| S5 | 前端注入 | 全部插入点均经过转义函数处理，覆盖 HTML 文本、属性与 SVG 文本三种上下文，未发现可利用点。转义函数在 SVG 语境下同样充分 |
| S6 | 数据外泄 | 全仓无任何对外网络请求、无遥测、无数据库、无落盘写操作；用户画像仅存在于进程内存，随机路径缓存存储的是仿真数组而非画像，且以内容哈希为键 |
| S7 | 启动配置 | 监听地址硬编码为回环地址，未暴露主机参数；调试模式固定关闭；无硬编码凭据 |

### （三）保留的残余风险

1. 进程崩溃时操作系统的内存转储可能包含当次画像，属操作系统层面行为，应用内无法完全规避。
2. 依赖清单只约束版本区间，未锁定具体版本与哈希。本地演示场景可接受，若对外分发应补锁定文件。
3. 缺少请求频率限制。互斥锁已能阻止并发推演堆积，但单机演示场景下未再引入限流层。

### （二）核实后确认无问题

前后端字段路径逐一核对一致；目标标识在两端的生成与使用约定一致；图表函数在空数组、单元素、全零、含空值等情形下均不抛异常；`Math.max.apply` 的数组长度受月份上限约束，不存在爆栈风险。

## 四、总体结论

三份评审未发现可被直接利用的致命或高危漏洞。发现的问题集中在三类：静默算出错误数值（缓存键漏字段、分位口径、短路径计数）、边界情形未覆盖（预算为零、输入无法解析、上下文畸形）、以及界面在异常路径下给出误导信息（结余为零、目标叙事错位）。

这三类问题的共同特征是**不会崩溃，只会给出看起来正常的错误答案**，在演示现场最难被发现。
