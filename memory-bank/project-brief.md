# 项目简报

## 一、基本信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 青智方舟 |
| 副标题 | Z 世代人生目标驱动式财务仿真与资产配置系统 |
| 赛事名称 | 赛事信息见交付说明 |
| 作品方向 | 青年群体服务 |
| 需求文档版本 | V1.0（2026 年 9 月 30 日编制） |
| 文档设定团队规模 | 三人（队长一名，技术成员两名） |

## 二、一句话定义

给收入不稳定的年轻人，把「这笔钱花不花」翻译成「那个目标会晚多久」，再把两个都说得通的取舍摆出来，由你自己挑。

## 三、产品性质

| 层面 | 说明 |
| --- | --- |
| 产品性质 | 面向收入不确定人群的财务决策辅助系统 |
| 时间方向 | 事前仿真与推演，而非事后记录与复盘 |
| 时间尺度 | 三到八年，覆盖学生到职场新人的过渡期 |
| 核心动作 | 仿真、分配、提示 |
| 用户关系 | 长期陪伴，而非单次理财服务 |

## 四、产品边界（强制约束）

以下的边界为强制条款，实现时不得越界：

1. 不是记账工具。不做收支流水记录、分类统计、账单导入。
2. 不是交易系统。不提供申购、赎回、转账等任何交易功能，不对接任何交易接口。
3. 不是销售平台。不做产品推荐排序、佣金展示、销量排行。
4. 不是收益预测工具。不预测具体产品的未来收益率，不承诺任何收益。
5. 不是风险测评问卷。不做传统的风险等级问卷打分，不输出 C1 至 C5 等级。

## 五、目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 主要用户　在校大学生 | 家庭支持为主，兼职与实习收入不稳定，有多个人生目标并行 | 想知道现在的消费方式会不会影响未来目标 |
| 次要用户　职场新人 | 刚工作，收入开始稳定但储蓄薄，面临租房、进修等支出 | 想知道能拿出多少钱做长期投资而不影响到近期刚需 |
| 演示用户　现场观众 | 在演示现场观看演示 | 想在几分钟内看懂产品的核心差异 |

## 六、核心价值

1. 把消费的机会成本可视化。不劝用户少花钱，而是让用户看到这笔钱花掉之后目标会推迟多久。
2. 把金融风险翻译成个人语言。不解释产品本身，而是说明这个波动对用户自己的目标意味着什么。
3. 承认成长性消费的价值。区分能提升未来收入能力的消费与纯情绪消费，给予不同的预算态度。
4. 适配不确定的收入。把兼职、奖学金、实习建模为可能中断的收入来源，而不是固定值。

## 七、两种产品形态（不得混用表述）

| 形态 | 说明 | 实现主体 |
| --- | --- | --- |
| 交付形态 | 本次交付的产出物：可本地运行的交互原型、仿真引擎、演示录屏、方案报告与演示材料 | 产品团队 |
| 落地形态 | 产品设想中的最终形态：嵌入银行手机银行的轻量财务模块，复用银行账户体系与在售产品池 | 由银行在被采纳后实现 |

演示时的表述纪律：演示环节表述为"原型已跑通"，落地环节表述为"接入方案"，两者不得交叉（对应规则 GR-10）。

## 八、可行性判断（当前分析结论）

1. **技术上可完成。** 产品的技术实质是规则引擎、蒙特卡洛模拟与图表呈现的组合，不涉及模型训练、高并发或实时数据管道，属于典型的单机应用范畴。
2. **单人开发的瓶颈不在算法而在角色负载。** 需求文档按三人分工撰写（队长负责叙事、两名技术成员分别负责建模与界面），实际全程单人推进，三份工作由一人承担，实现部分已完成，剩下的是核对、演示材料的准备。
3. **数据侧没有特殊依赖。** 交易接口、实时行情、征信数据、真实用户信息均被产品边界主动排除，参数与语料全部来自公开渠道，不需要授权、付费或对接持牌机构。

## 九、需求文档自身需要注意的两处问题

1. 文档设定的团队规模为三人，实际按单人推进，第 8.4 节的分工约定未生效。
2. 附录 A 中第 4、5、6 项参数的来源描述未给出具体机构与报告名称，属于演示时的薄弱环节。无法定位的已按决策 D-07 降级标注为假设，补齐具体报告仍是遗留项。
